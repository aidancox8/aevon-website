Security Policy

Mermaid, Markdown & LaTeX for Confluence · Effective 16 November 2026

Summary

The app runs entirely on Atlassian Forge. Aevon operates no servers for it, holds no customer data, and has no access to your Confluence site. The security of your content rests on Atlassian's platform and on the app keeping to the narrow permissions described below.

Architecture

  • Hosting. Atlassian Forge, on Atlassian's own infrastructure. There is no Aevon backend, database or file storage behind the app.
  • Network. The app declares no external egress in its manifest and makes no requests to any host outside Atlassian. All rendering libraries are bundled with the app; nothing is loaded from a CDN at run time.
  • Storage. The app uses no Forge storage and no browser storage. What you type into the macro is saved by Confluence as part of your page.
  • Authentication and tenant isolation. Handled by Atlassian Forge. The app has no login of its own and stores no credentials, tokens or secrets.

Permissions

The app requests two Confluence scopes, used only by the "Convert mermaid code blocks" action, which runs only when a user chooses it from the page menu and acts only on the page they are viewing, with that user's own permissions.

  • read:page:confluence: read the current page to find mermaid code blocks
  • write:page:confluence: save the converted page as a new version

Handling untrusted content

Macro content is written by your users and is treated as untrusted when it is rendered.

  • Raw HTML in Markdown is disabled in the parser.
  • Rendered Markdown output is sanitised with DOMPurify before it is added to the page.
  • Mermaid diagrams are rendered with Mermaid's strict security level, which disables script execution and click handlers in diagrams.
  • Rendering happens inside the sandboxed frame Atlassian provides for Forge apps, separate from the Confluence page itself.

Access by Aevon

Aevon staff cannot see your pages, your macro content or your users. The app sends nothing to us, so there is nothing for us to access, export or lose.

Dependencies and updates

The app depends on a small set of open-source libraries for rendering (markdown-it, Mermaid, KaTeX, highlight.js, DOMPurify) and on Atlassian's Forge packages. When a security fix is published for one of them that affects the app, an updated version of the app is released through the Atlassian Marketplace. Forge delivers updates that do not change permissions to installed sites automatically.

Reporting a vulnerability

Email hello@aevon.ca with "Security" in the subject line, a description of the issue and the steps to reproduce it. Reports are acknowledged within three business days. Please give us a reasonable chance to release a fix before disclosing publicly.

Vulnerabilities are fixed within the timeframes set by the Atlassian Marketplace Security Bug Fix Policy for cloud apps.

Security incidents

Because the app stores and transmits no customer data, an incident affecting the app itself cannot expose content held by Aevon. If a vulnerability in the app is found to have put customer sites at risk, Aevon will notify Atlassian as the Marketplace Partner agreement requires and publish the fix and the details on this page.
